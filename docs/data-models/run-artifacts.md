# Run and Sweep Artifact Schema

Scope: Canonical output artifacts generated by the benchmark client pipeline.

## Per-Run Artifact Set

Default location: `runs/<run_id>`.

Expected files:
- `requests.jsonl`
- `requests.csv`
- `per_bin_summary.csv`
- `throughput_latency_timeseries.csv`
- `server_metrics_timeseries.csv` (when telemetry scraping is enabled)
- `summary.json`
- `summary.md`
- `plots/` directory containing generated visualizations

## Sweep Artifact Set

Default location: `sweep_runs/`.

Expected files:
- `sweep_raw.csv`
- `sweep_summary.csv`
- `capacity_curve.png`
- `lambda{lambda}_rep{repeat}/` per-run subdirectories with standard run artifacts

## Artifact Ownership

- Client pipeline is the sole producer of benchmark artifacts.
- Server metrics exports are inputs to client artifact generation, not replacements for run artifacts.
- Artifact naming should be centrally defined in analysis schema utilities.

## Schema Expectations

- `requests.csv` mirrors `requests.jsonl` at row-level semantics.
- Summary artifacts include throughput and latency aggregates and indicate telemetry availability where applicable.
- Sweep summaries provide per-lambda aggregation across repeats, including TTFT/TPOT and total latency dimensions.

## Change Rules

Any artifact file/schema change requires synchronized updates to:
- this document,
- `docs/principles/artifact-contract.md`,
- `docs/operations/benchmark-recipes.md`,
- relevant analysis/report code.
